# LEC 3 · 从正则表达式生成词法分析器

SE3355 编译原理 · 2026 秋　[本讲课件（68 页）](../lectures/LEC-3-Lexical-Analysis-II.pptx)

两条规则 `IF = "if"`、`IDENT = letter (letter | digit)*` 都要读 `ifx` 的前两个字符。Lexer 生成器可以先把所有规则编成一部自动机。运行时读到 `if` 时关键字已经匹配成功，但紧接一个 `x`，最终就得返回标识符。自动机要同时记住**还能往哪里走**和**上一次在哪里能收词**。

## 从正则搭出 ε-NFA（p.5–26）

有限自动机由状态集 `Q`、字母表 `Σ`、转移函数 `δ`、起点和接受状态集 `F` 组成。DFA 对每个“状态、字符”只有一个下一状态。ε-NFA 可以沿同一字符走向多个状态，也可以沿 ε 边移动而不读字符。只要有一条路径恰好读完输入并停在接受状态，就接受这个串。两者都能识别且只能识别正则语言。

Thompson 构造给每个子表达式一个入口和一个出口。从内到外接线，每次只增加常数条边和状态，空间随正则的结构大小线性增长。

| 正则 | 怎样连接片段 |
| --- | --- |
| `c` 或 `ε` | 入口到出口连一条标记为 `c` 或 `ε` 的边。 |
| `AB` | 用 ε 边把 A 的出口接到 B 的入口。 |
| `A \| B`（选择） | 新入口分别通向 A、B，两者出口都通向新出口，四条均为 ε 边。 |
| `A*` | 新入口可直接去新出口，也可进入 A。A 的出口可回到 A 的入口，也可去新出口，四条均为 ε 边。 |

例如 `(1|0)*1` 的起点是 `s6`，终点是 `s9`。画图时先画 `1|0`，包上星号，最后串接必须读到的 `1`。

| 起点 | 边标签 | 终点 |
| --- | --- | --- |
| `s0` | `1` | `s1` |
| `s2` | `0` | `s3` |
| `s4` | `ε` | `s0`、`s2` |
| `s1`、`s3` | `ε` | `s5` |
| `s6` | `ε` | `s4`、`s7` |
| `s5` | `ε` | `s4`、`s7` |
| `s7` | `ε` | `s8` |
| `s8` | `1` | `s9` |

输入 `101` 时，一条路径让星号吃下 `10`，最后一条字符边吃下 `1`。若星号吃完整串，那条路径就到不了终点。有一条成功路径已经足够。

合并多条词法规则时另设公共起点，用 ε 边连向各规则入口。各接受状态保留自己的动作和优先级。以 **IF / IDENT** 为例，公共起点 `s0` 分别用 ε 边连到 `s1` 和 `s5`。两条路径按以下方式读字符。

| 规则 | 字符边与 ε 边 | 接受点 |
| --- | --- | --- |
| IF | `s1 —i→ s2 —ε→ s3 —f→ s4` | `s4` |
| IDENT | `s5 —letter→ s6 —ε→ s7`。从 `s7` 可沿 ε 边到 `s10` 结束，也可到 `s8` 继续。`s8` 读一个字母或数字到 `s9`，从 `s9` 可沿 ε 边回 `s8` 或到 `s10` 结束。 | `s10` |

因此，刚读完 `i` 时，两条路分别走到 `s2` 和 `s6`。从这两个状态再走所有可能的 ε 边，就能得到下表的 `C1`。

| 已读输入 | 当前 NFA 状态集合 | 接受候选 |
| --- | --- | --- |
| `ε` | `C0 = {s0,s1,s5}` | 无 |
| `i` | `C1 = {s2,s3,s6,s7,s8,s10}` | `IDENT` |
| `if` | `C2 = {s4,s8,s9,s10}` | `IF`、`IDENT` |

## 子集构造与最小化（p.27–36、43–50）

一个 DFA 状态代表“读完同一前缀后，NFA 可能处于的全部状态”。`move(S,c)` 收集从 S 中任一状态沿一条 `c` 边能到达的状态。`ε-closure(S)` 从 S 出发只走 ε 边，把起点本身也算进去。

1. 起点取 `ε-closure({start})`。
2. 从待处理队列取出集合 S，对每个字符类 c 计算 `T = ε-closure(move(S,c))`，记录 `S —c→ T`。从未见过的非空集合入队。空集可以记作死状态。
3. S 中只要有任一 NFA 接受状态，S 就接受。同一集合里的候选匹配长度相同，可预先记下优先级最高的动作。队列清空时，只构造了从起点可达的子集。

对上面的 `IF / IDENT`，另外两个集合是 `C_ID0 = {s6,s7,s8,s10}` 和 `C_ID = {s8,s9,s10}`。

| 当前状态 | 输入 | move 的结果 | ε 闭包 / 下一状态 |
| --- | --- | --- | --- |
| `C0` | `i` | `{s2,s6}` | `C1` |
| `C0` | 其他 letter | `{s6}` | `C_ID0` |
| `C0` | digit 或其他字符 | `∅` | `DEAD` |
| `C1` | `f` | `{s4,s9}` | `C2` |
| `C1` | 其余 letter/digit | `{s9}` | `C_ID` |
| `C_ID0` | letter/digit | `{s9}` | `C_ID` |
| `C2` | letter/digit | `{s9}` | `C_ID` |
| `C_ID` | letter/digit | `{s9}` | `C_ID` |

若直接运行这部 NFA，每读一个字符，就要对当前状态集合做一次 move 并补齐 ε 闭包。DFA 在生成阶段预先算出这些集合与转移，运行时每个字符只需查一次表。代价是 n 个 NFA 状态最多对应 2ⁿ 个子集。

**最小化要保留输出动作。** 初始把 `C0`（无输出）、`C2`（IF）各分一组，把 `C1、C_ID0、C_ID`（IDENT）分一组。同组中若有两个状态读某个字符后落入不同组，就拆分，直到分组稳定。对只判接受与否的自动机，初始按接受、非接受分组即可。

为什么 `C1` 必须单独留下？再读 `f`，它会走到 IF 组，而另外两者仍输出 IDENT。`C_ID0` 和 `C_ID` 对所有字符的去向都等价，可以合并。忽略统一的死状态，五个状态最后剩四个。

| 状态 | `i` | `f` | 其他 letter | digit | 其他 | accept |
| --- | --- | --- | --- | --- | --- | --- |
| `C0` | `C1` | `C_ID` | `C_ID` | DEAD | DEAD | NONE |
| `C1` | `C_ID` | `C2` | `C_ID` | `C_ID` | DEAD | IDENT |
| `C2` | `C_ID` | `C_ID` | `C_ID` | `C_ID` | DEAD | IF |
| `C_ID` | `C_ID` | `C_ID` | `C_ID` | `C_ID` | DEAD | IDENT |

表中的列互斥。先识别 `i` 和 `f`，其余字母才归入“其他 letter”。把字符类和状态编号，就可以用 `next[state][classOf(c)]` 直接查下一格。固定 DFA 判定一个长度为 m 的串，只需 O(m) 次转移。用它切分整份源码时，如果某轮回退很远，后续扫描仍会重读这段后缀。

## 运行时怎样找到词尾（p.39–42、51–58）

`state` 和当前位置用来尝试更长的匹配，`last` 保存最近一次接受的动作和结束位置。用只含 IF 和 IDENT 的表扫描 `ifx;`，会依次记下三个可以收词的位置。

| 操作 | 当前状态 | 当前接受动作 | lastAccept |
| --- | --- | --- | --- |
| 开始，位置 0 | `C0` | 无 | 无 |
| 消耗 `i`，位置 1 | `C1` | `IDENT` | `(IDENT, 1)` |
| 消耗 `f`，位置 2 | `C2` | `IF` | `(IF, 2)` |
| 消耗 `x`，位置 3 | `C_ID` | `IDENT` | `(IDENT, 3)` |
| 查看 `;`，无法转移 | 停止 | 无 | 保持 `(IDENT, 3)` |

若规则只有 `a` 和 `abc`，输入 `abx` 读到 `b` 后仍有路可走，却还没完成 `abc`。到 `x` 才知道走不通。此时退到 `a` 之后，`b`、`x` 都留给后面的扫描。到文件末尾时也要先交付已有的 `last`。回退时若维护行列号，必须一并恢复。

每个 mode 可有自己的起点、转移表和动作表。普通模式遇开引号时记录起点、进入字符串模式。字符串模式读内容时追加到缓冲区，读到闭引号时才发出包含整段位置的 Token。下面的伪代码也覆盖跳过空白和无匹配时的恢复。

```text
nextToken():
    while true:
        if atEOF(position):
            return finishAtEOF(mode)  # 正常返回 EOF，或诊断未闭合结构

        tokenStart = position
        table = tables[mode]
        state = table.start
        last = NONE

        while not atEOF(position):
            c = peek()
            target = table.next[state][classOf(c)]
            if target == DEAD:
                break

            state = target
            advanceOneCharacter()
            if table.accept[state] != NONE:
                last = (table.accept[state], position)

        if last == NONE:
            rewind(tokenStart)
            diagnoseInvalidCharacter(position)
            advanceOneCharacter()
            continue

        rewind(last.position)
        lexeme = input[tokenStart : position]
        span = [tokenStart, position)
        result = runAction(last.action, lexeme, span)

        if result emits a Token:
            return result.token
        # skip、append 或只切换 mode：继续寻找下一枚 Token
```

## 复习例子与工具（p.59–68）

期中题把普通字段名定义为“一个或多个字母，但排除恰好等于 `ws` 的串”。手画 DFA 时，只需记住空前缀、恰好 `w`、恰好 `ws` 和其他合法字母串这四种情况。单独识别普通字段名时，`w` 和“其他”接受，`ws` 不接受。若题目要求完整 DFA，还要补上死状态，所有非字母输入都进入它。在消息体模式里还要识别保留字，`ws` 就有了自己的接受动作。再读一个字母，两种情况都进入普通字段状态，所以 `wsx` 会整段作为普通字段。[期中复习课件，第 60–62 页](../lectures/LEC-17-Midterm-Review.pptx)

编译器 Lexer 按语言规约切词，输出有语法含义的类别和位置。BPE tokenizer 按训练得到的词表与合并规则把文本编码为 ID，一个源程序标识符可能被切成几个片段。用模型起草词法规约时，可以拿 `if`、`ifx`、不闭合的字符串等输入检查规则，再交给生成器构造自动机。下一步要判断这些 Token 能否组成程序。[第 4 讲 · 语法分析](LEC-4-Intro2Parsing.md)
