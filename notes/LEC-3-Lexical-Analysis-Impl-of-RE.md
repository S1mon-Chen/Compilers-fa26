## 1. 本讲主线：把词法规约编译成 Lexer（p.2–5、67）

上一讲规定了“应该怎样分词”，这一讲解决“怎样机械地生成执行这些规则的程序”。

```text
词法规约：patterns + actions + priority（按 mode 分组）
    ↓ Thompson 构造
ε-NFA：用容易组合的片段表示正则
    ↓ 子集构造
DFA：把 NFA 状态集合预先变成一个状态
    ↓ 最小化
更小的 DFA：合并当前与未来行为都相同的状态
    ↓ 编码为转移表和动作表
nextToken()：扫描、记录 lastAccept、回退、执行 action
    ↓
Token Stream + diagnostics
```

这里有两种不同的工作时机：

| 时机 | 工作 |
| --- | --- |
| 生成 Lexer 时 | 构造自动机、确定化、最小化、生成表格或代码 |
| Lexer 运行时 | 读取源程序、查表转移、执行动作、返回 Token |

**核心思想：把规则之间的共同扫描逻辑预先整理成有限状态，运行时每读一个字符只更新一个 DFA 状态。**

## 2. 为什么用自动机（p.5–11）

### 2.1 逐条匹配会重复读取相同前缀

贯穿本讲的两条规则是：

```text
IF    = "if"                    priority = 1
IDENT = letter (letter | digit)* priority = 2
```

其中优先级数值越小越优先。输入 `ifx` 时：

- `IF` 匹配 `if`，长度为 2。
- `IDENT` 匹配 `ifx`，长度为 3。
- 最长匹配选择 `IDENT("ifx")`。

逐条实现能得到正确结果，但会重复读取 `i`、`f`。规则越多，共同前缀可能被检查越多次。

### 2.2 状态记录“已经读到哪里，以及未来还可能怎样”

手工合并这两条规则，可以得到四种情况：

| 状态 | 已读前缀的情况 | 当前能接受什么 |
| --- | --- | --- |
| `START` | 尚未读取字符 | 无 |
| `S_i` | 恰好读到 `i` | `IDENT` |
| `S_if` | 恰好读到 `if` | `IF`、`IDENT`，同长选 `IF` |
| `S_ID` | 已进入普通标识符 | `IDENT` |

读到 `if` 后，仍要看下一个字符：若是字母或数字，就继续匹配标识符。**到达接受状态，只表示当前前缀可以成为一个 Token，并不表示应该立即返回。**

## 3. 有限自动机：DFA 与 NFA（p.9–10）

有限自动机（Finite Automaton，FA）用五元组表示：

$$
A=(Q,\Sigma,\delta,q_0,F)
$$

| 符号 | 含义 |
| --- | --- |
| $Q$ | 有限状态集合 |
| $\Sigma$ | 输入字母表，Lexer 中通常是字符或字符类 |
| $\delta$ | 状态转移规则 |
| $q_0$ | 初始状态 |
| $F\subseteq Q$ | 接受状态集合 |

### 3.1 DFA：确定有限自动机

$$
\delta:Q\times\Sigma\to Q
$$

给定当前状态和输入字符，下一状态唯一。运行时只需要维护一个 `currentState`。

**补充理解：** 形式定义通常要求转移函数是全函数。实际 Lexer 可以省略失败边，把这些边统一解释为 `DEAD`。若要补成完整 DFA，可加入一个读任何字符都回到自身的死状态。

### 3.2 NFA：非确定有限自动机

本讲允许 ε 转移，因此更准确地说是 ε-NFA：

$$
\delta:Q\times(\Sigma\cup\{\varepsilon\})\to\mathcal P(Q)
$$

$\mathcal P(Q)$ 表示 $Q$ 的幂集，即所有状态子集组成的集合。一次转移可能到达零个、一个或多个状态。

- 字符边消耗一个输入字符。
- ε 边不消耗输入。
- NFA 运行时可以维护所有仍可能成功的状态。
- 对完整字符串，只要存在一条消耗全部输入并到达接受状态的路径，就接受该字符串。

**DFA 与 NFA 识别能力相同，都识别正则语言。** NFA 方便构造，DFA 方便执行。

## 4. Thompson 构造：Regex → ε-NFA（p.12–18）

### 4.1 片段的统一接口

每个正则子表达式都对应一个 NFA 片段，暴露一个 `entry` 和一个 `exit`。按照正则的结构递归拼接片段，保证：

$$
L(\operatorname{NFA}(R))=L(R)
$$

本讲使用四类构造：基本片段、连接、选择、重复。组合时只连接片段边界，不需要修改内部结构。

### 4.2 基本片段：字符与空串

```text
字符 c：entry --c--> exit
空串 ε：entry --ε--> exit
```

字符片段恰好消耗一个 `c`；空串片段不消耗输入。

### 4.3 连接 AB

```text
A.entry ... A.exit --ε--> B.entry ... B.exit
```

- 新片段的入口是 `A.entry`。
- 新片段的出口是 `B.exit`。
- 必须先匹配 A，再匹配 B。

### 4.4 选择 A | B

新增入口 `u`、出口 `v`，添加四条 ε 边：

```text
u      --ε--> A.entry
u      --ε--> B.entry
A.exit --ε--> v
B.exit --ε--> v
```

两条分支同时保留，后续输入会淘汰不可能的路径。

### 4.5 重复 A*

同样新增入口 `u`、出口 `v`，添加四条 ε 边：

```text
u      --ε--> v         # 零次：直接跳过
u      --ε--> A.entry   # 开始匹配 A
A.exit --ε--> A.entry   # 再匹配一次 A
A.exit --ε--> v         # 结束重复
```

**零次路径和循环路径缺一不可。** 没有跳过路径就不能直接表达零次，没有回边就不能表达任意多次。

### 4.6 为什么规模是线性的

每个基本构造只引入常数个状态和边，因此按上述模板构造的 NFA 规模为 $O(|R|)$，其中 $|R|$ 是正则表达式的结构大小。

**补充理解：** `A+`、`A?` 等扩展写法可以先改写为基本运算，例如 `A+ = AA*`、`A? = A | ε`。字符类也可以直接作为边上的匹配条件。

## 5. Thompson 构造例子：(1 | 0)*1（p.19–22）

目标语言是：**所有以 `1` 结尾的非空二进制串**。

按课件编号，构造顺序如下：

1. 字符片段：`s0 --1--> s1`，`s2 --0--> s3`。
2. 选择：增加入口 `s4`、出口 `s5`，得到 `1 | 0`。
3. 重复：增加入口 `s6`、出口 `s7`，得到 `(1 | 0)*`。
4. 连接：新增 `s8 --1--> s9`，用 `s7 --ε--> s8` 接上最后的 `1`。

最终起始状态为 `s6`，接受状态为 `s9`。完整边集如下，便于对照课件重画：

| 起点 | 边标签 | 终点 |
| --- | --- | --- |
| `s0` | `1` | `s1` |
| `s2` | `0` | `s3` |
| `s4` | `ε` | `s0`、`s2` |
| `s1`、`s3` | `ε` | `s5` |
| `s6` | `ε` | `s4`、`s7` |
| `s5` | `ε` | `s4`、`s7` |
| `s7` | `ε` | `s8` |
| `s8` | `1` | `s9` |

**补充理解：** 对输入 `101`，重复部分可以消耗前两个字符 `10`，最后的字符片段消耗末尾的 `1`。虽然重复部分也可能尝试消耗全部 `101`，这条路径会因缺少最后的 `1` 而失败，但不影响另一条成功路径。

| 输入 | 是否接受 | 原因 |
| --- | --- | --- |
| `ε` | 否 | 最后的 `1` 必须出现 |
| `1` | 是 | 重复部分匹配零次 |
| `001`、`101` | 是 | 最后一位为 `1` |
| `0`、`110` | 否 | 最后一位为 `0` |

## 6. 合并多条 Token 规则（p.23–26）

分别构造各条规则的 NFA，再增加一个公共起点，通过 ε 边连接各规则入口。

接受状态需要保留的不只是“接受”这个布尔值，还包括：

- 对应的规则或 Token 类别。
- 匹配成功后执行的 action。
- 同长冲突时使用的 priority。

课件中 `IF` 的接受状态为 `s4`，`IDENT` 的接受状态为 `s10`。扫描时的集合变化是：

| 已读输入 | 当前 NFA 状态集合 | 接受候选 |
| --- | --- | --- |
| `ε` | `C0 = {s0,s1,s5}` | 无 |
| `i` | `C1 = {s2,s3,s6,s7,s8,s10}` | `IDENT` |
| `if` | `C2 = {s4,s8,s9,s10}` | `IF`、`IDENT` |

在 `C2` 中，两条规则都匹配长度 2，因此同长时选 `IF`。若后面还有字母或数字，则仍需继续探索更长的 `IDENT`。

这启发了确定化：**把一个完整的 NFA 状态集合命名为一个 DFA 状态。**

## 7. 子集构造：NFA → DFA（p.27–36）

### 7.1 两个基本集合运算

**`move(S, c)`：** 从集合 S 中任一状态出发，沿一条字符 c 边直接到达的所有状态。

$$
\operatorname{move}(S,c)=\{q'\mid\exists q\in S,\ q\xrightarrow{c}q'\}
$$

**`ε-closure(T)`：** 从 T 中任一状态出发，沿零条或多条 ε 边可到达的所有状态。因为允许零条边，所以：

$$
T\subseteq\varepsilon\text{-closure}(T)
$$

一次 DFA 转移为：

$$
S'=\varepsilon\text{-closure}(\operatorname{move}(S,c))
$$

顺序是：**先消耗一个字符，再补齐所有不消耗输入的 ε 路径。** 当前集合 S 本身已经是 ε 闭包，因此其字符转移前的 ε 路径也已包含在内。

**补充理解：** 求 ε 闭包时可使用栈或队列，并用 `visited` 避免在 ε 环上无限循环。

### 7.2 用 worklist 枚举可达集合

```text
start = epsilonClosure({nfa.start})
discovered = {start}
worklist = [start]

while worklist 非空:
    S = pop(worklist)
    for 每一种输入字符类 c:
        T = epsilonClosure(move(S, c))
        if T 为空集:
            next[S, c] = DEAD
        else:
            next[S, c] = T
            if T 不在 discovered 中:
                加入 T 到 discovered
                加入 T 到 worklist
```

- `discovered` 保存已经发现的集合，避免重复建状态。
- `worklist` 保存尚未展开全部出边的集合。
- 集合按成员判断是否相同，不受成员排列顺序影响。
- 只构造从起点可达的子集，不必列出整个幂集。

若 NFA 有 N 个状态，最多存在 $2^N$ 个子集，因此算法会终止，但最坏情况下可能产生指数数量的 DFA 状态。

### 7.3 如何继承接受状态和动作

DFA 状态 S 接受，当且仅当：

$$
S\cap F_{NFA}\ne\varnothing
$$

S 中可能同时包含多条规则的接受状态。它的候选动作由这些状态共同决定；在当前匹配长度固定时，选择 priority 最小的规则。

**补充理解：** 可以在生成阶段就为每个 DFA 状态预先选出同长最优 action。运行阶段每次到达更晚的接受位置，再覆盖 `lastAccept`，仍然实现“先最长、再优先级”。

### 7.4 IF / IDENT 的完整可达子集

除 `C0`、`C1`、`C2` 外，还会发现两个集合：

```text
C_ID0 = {s6,s7,s8,s10}
C_ID  = {s8,s9,s10}
```

下面把课件 p.30–36 的逐步展开汇总为一张表：

| 当前状态 | 输入 | move 的结果 | ε 闭包 / 下一状态 |
| --- | --- | --- | --- |
| `C0` | `i` | `{s2,s6}` | `C1` |
| `C0` | 其他 letter | `{s6}` | `C_ID0` |
| `C0` | digit 或其他字符 | `∅` | `DEAD` |
| `C1` | `f` | `{s4,s9}` | `C2` |
| `C1` | 其余 letter/digit | `{s9}` | `C_ID` |
| `C_ID0` | letter/digit | `{s9}` | `C_ID` |
| `C2` | letter/digit | `{s9}` | `C_ID` |
| `C_ID` | letter/digit | `{s9}` | `C_ID` |

后四个状态遇到不属于 letter/digit 的字符都进入 `DEAD`。接受信息为：

```text
C0   : NONE
C1   : IDENT
C_ID0: IDENT
C2   : IF + IDENT → 同长选 IF
C_ID : IDENT
```

## 8. 最长匹配与 lastAccept（p.39–42）

### 8.1 两个规则，顺序不能颠倒

1. **Maximal munch：** 选择能匹配的最长前缀。
2. **Priority：** 只在最长前缀对应的同长候选之间选择优先规则。

因此 `IF` 优先级再高，也不能把 `ifx` 切成 `IF("if")` 与 `IDENT("x")`。

### 8.2 current 与 lastAccept 分别做什么

| 记录 | 含义 | 更新时机 |
| --- | --- | --- |
| `currentState/currentPos` | 为探索更长匹配走到的位置 | 每次成功转移后 |
| `lastAcceptAction/lastAcceptPos` | 最近一次能够合法结束的位置与动作 | 进入接受状态后 |

探索可能经过非接受状态，因此停止时应提交 `lastAccept`，而不是直接提交当前状态。

### 8.3 扫描 ifx;

位置采用从 0 开始的偏移，接受位置指向已匹配文本的末尾之后。

| 操作 | 当前状态 | 当前接受动作 | lastAccept |
| --- | --- | --- | --- |
| 开始，位置 0 | `C0` | 无 | 无 |
| 消耗 `i`，位置 1 | `C1` | `IDENT` | `(IDENT, 1)` |
| 消耗 `f`，位置 2 | `C2` | `IF` | `(IF, 2)` |
| 消耗 `x`，位置 3 | `C_ID` | `IDENT` | `(IDENT, 3)` |
| 查看 `;`，无法转移 | 停止 | 无 | 保持 `(IDENT, 3)` |

结果：返回 `IDENT("ifx")`，下一轮从 `;` 开始。此处示例自动机只有 IF 和 IDENT；完整 Lexer 还需要分号、空白等规则。

对于 `if `，最后接受记录是 `(IF, 2)`，因此返回 `IF`，空格留给下一轮处理。

### 8.4 真正需要向前回退的情形（补充理解）

设规则为 `A = a`、`ABC = abc`，输入为 `abx`：

```text
读 a：接受 A，记录 lastAcceptPos = 1
读 b：仍可能匹配 abc，但当前 ab 不接受
看 x：无法继续
回到位置 1，提交 A("a")
下一轮从 b 开始
```

这说明回退可能跨过已经消耗的字符。`lastAccept` 的作用不仅是避免吞掉触发失败的字符。

## 9. NFA 与 DFA 的成本比较（p.43）

| 维度 | NFA | DFA |
| --- | --- | --- |
| 构造 | Thompson 模板容易组合 | 需要枚举可达子集 |
| 状态规模 | 对正则结构大小为线性规模 | 最坏可能指数膨胀 |
| 运行时状态 | 一个状态集合 | 一个状态编号 |
| 处理字符 | `move + ε-closure` | 一次查表或 `switch` |
| 典型用途 | 构造中间表示、部分运行时引擎 | 提前生成的高效扫描器 |

**补充理解：** 对固定 DFA 做一次不回退的字符串识别，扫描长度 n 的输入需要 $O(n)$ 次转移。带 maximal munch 回退的完整 Lexer 若反复重扫很长后缀，整体复杂度还要单独分析，不能仅凭“每次转移是常数时间”就断言所有规约都保证整段输入线性时间。

## 10. DFA 最小化：按行为合并状态（p.44–50）

### 10.1 当前输出相同，只是第一关

两个状态能够合并，需要满足：

1. 当前接受行为一致：非接受与非接受对应；接受状态的最终 action 相同。
2. 对每一类未来输入，要么双方都停止，要么转移到仍然等价的状态。

Lexer 的接受状态带有 action，因此不能仅按“是否接受”划分。`IF` 和 `IDENT` 都接受，但输出不同，不能直接合并。

### 10.2 分组细化算法

```text
P = 按最终 action 分组，非接受状态单独成组

重复:
    检查每一个组 G
    检查每一种输入字符类 c
    按 next[state, c] 所属的组拆分 G
    无转移统一视为 STOP
直到没有组发生变化

把每个最终分组合并成一个状态
```

这里比较的是“下一状态所在的组”，不是要求下一状态编号完全相同。每次拆分后都需要重新检查，直到达到固定点。

### 10.3 IF / IDENT 的细化过程

初始按 action 分组：

```text
P0 = {
    {C0},                 # 不接受
    {C1, C_ID0, C_ID},     # emit IDENT
    {C2}                  # emit IF
}
```

用后续字符 `f` 检查 IDENT 组：

| 状态 | 读入 `f` 后 | 下一站的组 |
| --- | --- | --- |
| `C1` | `C2` | IF 组 |
| `C_ID0` | `C_ID` | IDENT 组 |
| `C_ID` | `C_ID` | IDENT 组 |

所以 `C1` 必须拆出来。它记住了“之前恰好读到 i”，因此未来遇到 `f` 时行为不同。

继续检查所有输入类，`C_ID0` 与 `C_ID` 的行为始终一致：字母/数字都进入 `C_ID`，其余字符都停止。最终：

```text
P* = { {C0}, {C1}, {C_ID0, C_ID}, {C2} }
```

五个可达非死状态缩减为四个，合并后的标识符状态仍记为 `C_ID`。**子集构造得到的不同 NFA 子集，可能具有相同的未来行为，因此确定化之后仍可最小化。**

## 11. Lexer mode：按上下文选择 DFA（p.51–53）

同一字符在不同上下文中可以有不同意义。例如，普通代码中的空格可能被跳过，字符串中的空格属于内容。

课件采用每个 mode 独立生成一台 DFA 的方案：

```text
NORMAL rules → NFA_NORMAL → DFA_NORMAL → 独立最小化
STRING rules → NFA_STRING → DFA_STRING → 独立最小化
```

运行时由 `currentMode` 选择本轮使用的转移表和入口。

| 当前 mode | 匹配到的内容 | action |
| --- | --- | --- |
| `NORMAL` | 标识符 | emit IDENT |
| `NORMAL` | 开引号 | 进入 STRING |
| `STRING` | 字符串内容 | append 到字符串缓冲区 |
| `STRING` | 闭引号 | emit STRING，返回 NORMAL |

最长匹配和规则优先级只在当前 mode 启用的规则内部比较。模式切换由成功匹配后的 action 完成。

**补充理解：** mode 方案还需要处理转义、未闭合字符串等语言规则；课件的小 DFA 只展示组织方式。字符串 Token 可以跨越多次内部匹配，因此缓冲区及整个字符串的起始位置要由 action 额外保存。

## 12. 从 DFA 生成表驱动代码（p.54–58）

### 12.1 字符分类与转移表

输入字符类需要能唯一确定查表列。对本例划分为：`i`、`f`、其他 letter、digit、其他字符。

| 状态 | `i` | `f` | 其他 letter | digit | 其他 | accept |
| --- | --- | --- | --- | --- | --- | --- |
| `C0` | `C1` | `C_ID` | `C_ID` | DEAD | DEAD | NONE |
| `C1` | `C_ID` | `C2` | `C_ID` | `C_ID` | DEAD | IDENT |
| `C2` | `C_ID` | `C_ID` | `C_ID` | `C_ID` | DEAD | IF |
| `C_ID` | `C_ID` | `C_ID` | `C_ID` | `C_ID` | DEAD | IDENT |

**补充理解：** `i`、`f` 本身也是字母，`classOf()` 应先区分它们，再把剩余字母归入 LETTER，确保类别互斥。更一般地，只有在所有相关状态上转移行为一致的字符，才适合共用一列。

### 12.2 编码为数组

```text
状态编号：C0=0, C1=1, C2=2, C_ID=3
字符类：  I=0, F=1, LETTER=2, DIGIT=3, OTHER=4
DEAD = -1

next = [
    [1, 3, 3, -1, -1],
    [3, 2, 3,  3, -1],
    [3, 3, 3,  3, -1],
    [3, 3, 3,  3, -1]
]

accept = [NONE, IDENT, IF, IDENT]
startState[NORMAL] = 0
```

生成物主要包括 `next`、`accept`、`startState` 和字符分类函数或表 `classOf()`。也可以把相同逻辑生成为 `switch`。

### 12.3 通用 nextToken() 循环

下面在课件扫描循环基础上补全 EOF、skip 和错误恢复，便于理解完整流程；这些边界处理属于**补充理解**。

```text
nextToken():
    while true:
        if atEOF(position):
            return finishAtEOF(mode)  # 正常返回 EOF，或诊断未闭合结构

        tokenStart = position
        table = tables[mode]
        state = table.start
        last = NONE

        while not atEOF(position):
            c = peek()
            target = table.next[state][classOf(c)]
            if target == DEAD:
                break

            state = target
            advanceOneCharacter()
            if table.accept[state] != NONE:
                last = (table.accept[state], position)

        if last == NONE:
            rewind(tokenStart)
            diagnoseInvalidCharacter(position)
            advanceOneCharacter()
            continue

        rewind(last.position)
        lexeme = input[tokenStart : position]
        span = [tokenStart, position)
        result = runAction(last.action, lexeme, span)

        if result emits a Token:
            return result.token
        # skip、append 或只切换 mode：继续寻找下一枚 Token
```

需要注意：

- `peek()` 不消耗字符，只有合法转移才前进。
- `last` 保存的是已匹配部分之后的位置，便于截取左闭右开的 lexeme。
- 即使已经消耗了非接受前缀，失败且无候选时也要采用明确的恢复策略；这里选择回到本轮起点并跳过一个字符。
- 到达 EOF 后，若已有 `last`，先提交它；下一次扫描再处理 EOF。
- 本循环假定普通 Token 规则不会匹配空串，否则可能反复执行动作而不前进。EOF 应作为单独条件处理。
- 若维护行号、列号，回退时也必须恢复相应位置记录。

## 13. 两种 Tokenizer 的区别（p.59–61）

| 维度 | 编译器 Lexer | 课件中的 BPE tokenizer |
| --- | --- | --- |
| 依据 | 语言设计者写下的词法规约 | 从语料学到的词表与合并规则 |
| 边界确定方式 | 正则、最长匹配、规则优先级 | 固定词表和编码规则 |
| 输出 | kind、value/lexeme、span | 片段对应的 token ID |
| 目的 | 为 Parser 提供有语法意义的类别 | 用有限词表编码文本 |

BPE 的训练阶段统计相邻片段并逐步合并；使用阶段使用已经确定的词表和规则，不会为每次输入重新训练。

课件用 `getHTTPResponseCode → get / HTTP / Response / Code` 展示子词切分思路。**补充理解：** 这是示意，具体切分依赖 tokenizer 的词表和实现，不能据此推断任意实际模型的结果。固定 tokenizer 的编码过程也可以是确定的，两者的主要区别在于分词依据和用途。

## 14. 确定性生成器与 LLM 的分工（p.62–66）

课件提出一种工作流程：

```text
人的意图、示例与约束
    ↓ LLM 协助提出候选、补充边界情况
审查后的正式规约
    ↓ 确定性生成器执行机械转换
实现
    ↓ 测试、静态检查、差分与覆盖率
验证证据
```

对于 IF / IDENT，设计者需要决定数字能否开头、关键字与标识符怎样冲突；生成器负责忠实地把这些决定落实为自动机与代码。

**补充理解：** 构造算法保持规约语义，不等于规约已经正确表达人的意图，生成器实现本身也需要验证。示例测试 `if → IF`、`ifx → IDENT` 用于检查设计意图是否得到满足。

课件中的 `1x → ERROR` 基于这里只启用 IF 和 IDENT 两条规则：数字不能作为任何规则的开头。它不是对所有语言的普遍结论；如果另有数字规则，或报错后继续恢复，结果会由完整规约决定。

## 15. 易错点与复习自测

| 易错点 | 正确理解 |
| --- | --- |
| ε 边消耗一个“空字符” | ε 边完全不消耗输入 |
| ε 闭包不包含起点 | 零条边也允许，所以包含原集合 |
| `move` 会自动走完 ε 边 | `move` 只走一条字符边，之后再求 ε 闭包 |
| NFA 需要先猜一条分支 | 可以同时维护所有仍可能成功的状态 |
| 接受状态应立即 emit | 先记录，再继续寻找更长匹配 |
| 高优先级规则总是先赢 | 先比较匹配长度，同长才比较优先级 |
| 输出同一 Token 就能合并 | 还要比较所有未来输入的行为 |
| 子集构造自动得到最小 DFA | 不同子集仍可能等价，需要进一步最小化 |
| DEAD 表示丢掉当前字符 | 结束探索，回到最后接受位置；无候选才走错误恢复 |

1. **Regex → NFA 为什么容易机械化？**  
   正则由有限种结构递归组成，每种结构都有固定的 Thompson 片段模板。

2. **一个 DFA 状态代表什么？**  
   子集构造中，它代表读取同一前缀后 NFA 所有可能状态的 ε 闭包集合。

3. **为什么 NFA → DFA 不会丢失接受路径？**  
   每步先收集全部字符转移，再补齐所有 ε 可达状态；集合始终保留读完当前前缀后所有可能到达的状态。

4. **为什么 `ifx` 返回 IDENT，而不是 IF？**  
   IDENT 匹配长度 3，IF 只匹配长度 2，最长匹配先于规则优先级。

5. **为什么 `C1` 与 `C_ID` 不能合并？**  
   后续字符 `f` 可以区分两者：前者到达 IF 接受状态，后者仍接受 IDENT。

6. **为什么 `C_ID0` 与 `C_ID` 可以合并？**  
   当前 action 相同，且对每一类后续输入都转移到相同的组或同时停止。

7. **如果停止时 current 不接受，但 lastAccept 存在，应该怎么办？**  
   回退到 lastAccept 的位置，执行已保存的 action，把探索多读的后缀留给后续扫描。

8. **mode 在什么地方生效？**  
   每轮扫描开始时选择规则组对应的 DFA，匹配成功后的 action 可以切换 mode。

9. **下一讲还需要解决什么？（p.68）**  
   Lexer 已经得到 Token 流，但任意深度的括号嵌套、分支结构、表达式优先级与结合性仍需 Parser 和上下文无关文法（CFG）处理。
