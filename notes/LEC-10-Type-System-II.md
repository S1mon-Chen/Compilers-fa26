## 1. 本讲主线：恢复被省略的类型（p.2–11）

上一讲的检查器大致是：

```text
check(e, Γ) → T

递归检查子节点 → 应用当前节点规则 → 返回类型
```

对于 `fun (x : Int) -> Int { x + 1 }`，参数标注把 `x : Int` 放入环境，检查器可以验证加法规则。删去标注后：

```text
fun x { x + 1 }
```

Resolver 仍能确定 `x` 指向哪个参数，但原来的检查器缺少参数类型。类型推导（type inference）要利用 `x + 1` 对操作数的要求，恢复 `x : Int`。

| 问题 | 类型检查 | 类型推导 |
| --- | --- | --- |
| 已有信息 | 标注、环境、子表达式类型 | 相同信息，但允许缺少部分类型 |
| 规则的作用 | 核对类型是否符合要求 | 产生约束，并核对这些约束能否同时成立 |
| 未知类型 | 上一讲的算法要求先有类型来源 | 用类型变量占位 |
| 成功结果 | 类型判断成立 | 找到替换，使类型判断成立 |

本讲的核心流程：

```text
AST + 类型规则
       ↓
候选类型 T、约束 C
       ↓ unification
替换 S
       ↓ 应用到类型、环境和 AST
带类型的程序
```

### 1.1 省略标注仍然可以是静态类型

课件用 C++ 说明：

```cpp
auto x = 42;   // 推导为 int
x = 7;         // 合法
x = "hello";   // 类型错误
auto y;        // 缺少初始化式，无法这样声明
```

`auto` 让编译器在声明处确定类型。后续对 `x` 的使用仍受 `int` 的规则约束，变量不会因为下一次赋值而重新推导为字符串类型。具体规则见 [C++ 工作草案：Placeholder type specifiers](https://eel.is/c++draft/dcl.spec.auto)。

**类型从哪里得到，与类型在何时检查，是两个不同维度。** 类型推导可以服务于静态检查；不写类型标注不等于动态类型。

## 2. 类型变量、候选类型与替换（p.13–22）

### 2.1 在 SimpleType 中允许缺失标注

```text
上一讲：
    fun (x : T1) -> T2 { e }
    let x : T = e1 in e2

本讲：
    fun x { e }
    let x = e1 in e2
```

推导过程中使用的类型语法扩展为：

```text
T ::= Int | Bool | α | T -> T
```

`α`、`β`、`γ` 是编译器内部的**待求解类型变量**，可以最终替换为基本类型，也可以替换为整个函数类型。

| 记号 | 含义 |
| --- | --- |
| `Γ` | 类型环境；单态阶段将变量或 Symbol 映射到类型 |
| `fresh()` | 创建一个此前未使用的类型变量 |
| `T` | 候选类型，可能含未知类型变量 |
| `C` | 从程序生成的类型等式集合 |
| `E` | 合一过程中尚未解决的等式 |
| `S` | 替换（substitution），如 `{α ↦ Int}` |
| `S(T)` | 将替换应用到类型 T |
| `FV(T)` | T 中自由类型变量的集合 |

**补充理解：** 本文箭头按右结合解释：`A -> B -> C` 是 `A -> (B -> C)`；函数作为参数时写成 `(A -> B) -> C`。

### 2.2 `fresh` 与共享变量分别表达什么

```text
fun x { x + x }
```

进入函数体时为参数创建一个 `α`，两处 `x` 都从同一环境绑定取得 `α`，表示同一个参数只有一个类型。

两个互不相关的新参数则应创建不同变量。若都误用同一个 `α`，就会添加程序本来没有要求的同型关系。

这里应区分：

- **创建新的未知类型位置**：使用 `fresh()`。
- **查询同一个单态绑定**：复用已有变量。
- **使用多态绑定**：后文将只为被量化的变量创建 fresh 实例。

### 2.3 替换必须作用于整个类型结构

```text
S = { α ↦ Int, β ↦ Bool }

S(α)         = Int
S(α → β)     = Int → Bool
S((α → β) → α) = (Int → Bool) → Int
```

求解成功后的目标是：

$$
\operatorname{infer}(\Gamma_0,e)=(T_0,C),\quad
\operatorname{unify}(C)=S
\quad\Longrightarrow\quad
S(\Gamma_0)\vdash e:S(T_0)
$$

候选类型和约束需要配套保存。只得到 `α -> Int`，却丢掉 `α = Int`，会损失函数体已经提供的信息。

**补充理解：** 求解成功不要求所有类型变量都变成 `Int` 或 `Bool`。例如恒等函数没有约束参数的具体类型；剩余变量是否可以泛化，要看环境及语言规则。

## 3. 类型规则如何生成约束（p.16–20、24–34）

### 3.1 以 `fun x { x + 1 }` 为例

```text
准备：α = fresh()，Γ₁ = Γ₀[x ↦ α]

Add
├── Name(x)     返回 α
└── Int(1)      返回 Int

[ADD] 要求：左边 = Int，右边 = Int
新增约束：α = Int
加法返回：Int

[FUN] 返回候选类型：α → Int
```

合一得到 `S = {α ↦ Int}`，所以函数最终为 `Int -> Int`。

**当前节点的返回类型，与当前节点新增的约束，是两份不同的信息。** 加法返回 `Int`，同时要求参数的未知类型满足 `α = Int`。

### 3.2 规则速查表

下表在课件的单态约束生成模型上整理，并将上一讲的 `<`、`if` 规则按同样方式展开。所有行都要合并子表达式产生的约束。

| 表达式 | 子节点或环境提供的类型 | 本节点新增约束 | 返回的候选类型 |
| --- | --- | --- | --- |
| 整数 `n` | 无 | 无 | `Int` |
| `true` / `false` | 无 | 无 | `Bool` |
| 变量 `x` | `Γ(x)=T` | 无 | `T` |
| `e1 + e2` | `T1`、`T2` | `T1=Int`，`T2=Int` | `Int` |
| `e1 < e2` | `T1`、`T2` | `T1=Int`，`T2=Int` | `Bool` |
| `if c then a else b` | `Tc`、`Ta`、`Tb` | `Tc=Bool`，`Ta=Tb` | `Ta` |
| `fun x { e }` | 在 `Γ[x↦α]` 中推导主体得到 `Tb` | 无额外等式，α 为 fresh | `α -> Tb` |
| `f(a)` | `Tf`、`Ta` | `Tf = Ta -> β`，β 为 fresh | `β` |
| `let x=e1 in e2` | 先得 `T1`，再在 `Γ[x↦T1]` 中得到 `T2` | 单态版本无额外等式 | `T2` |

像 `Int = Int` 这样的恒等式可以生成后删除，也可以在生成时直接省略。课件示例采用后者。

**补充理解：** 显式标注仍可参与推导。例如 `fun x -> Bool { x + 1 }` 会要求主体类型 `Int = Bool`，因而失败。标注提供额外约束，不能覆盖函数体推导出的事实。

### 3.3 函数调用为什么要构造一个箭头类型

上一讲的调用规则是：

$$
\frac{\Gamma\vdash f:T_1\to T_2\qquad\Gamma\vdash a:T_1}
     {\Gamma\vdash f(a):T_2}
\;[\mathrm{APP}]
$$

推导时，`Tf` 可能只是一个未知变量，还无法直接读取它的参数类型和结果类型。因此统一处理为：

```text
β = fresh()
加入 Tf = Ta → β
返回 β
```

这条约束同时表达：被调用对象必须是函数、它必须能接收该实参、调用结果为 `β`。

| 已知信息 | 产生的等式 | 后续结果 |
| --- | --- | --- |
| `Tf=α`，`Ta=Int` | `α = Int -> β` | 将 α 约束成函数类型 |
| `Tf=Int -> Bool`，`Ta=Int` | `Int -> Bool = Int -> β` | 得到 `β=Bool` |
| `Tf=Bool`，`Ta=Int` | `Bool = Int -> β` | 构造器冲突 |

课件 p.33 的讲者备注也指出：已知 `Tf` 是箭头类型时，可以直接检查参数并返回结果类型；上述模板适用于 `Tf` 仍未知的通用情况。

### 3.4 后序处理仍然需要环境准备

普通表达式先处理子节点，再处理父节点。但必须在进入函数体前加入参数绑定，在进入 `let` 主体前加入局部绑定。

```text
进入 fun：建立参数绑定
    → 递归主体
    → 构造函数类型

进入 let：递归初始化式
    → 建立 let 绑定
    → 递归主体
    → 返回主体类型
```

这里继续使用**非递归 let**：新名字在初始化式中不可见。支持递归绑定需要另行设计。

## 4. 完整案例：逐节点生成约束（p.24–34）

```text
let f = fun x {
    x + 1
} in f(1)
```

### 4.1 环境与 AST

```text
Γ₀ = ∅
Γ₁ = { x : α }         // 检查函数体
Γ₂ = { f : α → Int }   // 检查 let 主体，当前仍用单态绑定

Let [8]
├── init: Fun [4]
│   └── Add [3]
│       ├── Name(x) [1]
│       └── Int(1)  [2]
└── body: App [7]
    ├── Name(f) [5]
    └── Int(1)  [6]
```

`[1]`–`[8]` 是节点处理顺序。进入作用域的准备动作发生在相应子树之前。

### 4.2 每个节点提供什么信息

| 顺序 | 节点 | 环境 | 新增约束 | 返回类型 |
| --- | --- | --- | --- | --- |
| 1 | `x` | `Γ₁` | 无 | `α` |
| 2 | 函数体中的 `1` | `Γ₁` | 无 | `Int` |
| 3 | `x + 1` | `Γ₁` | `α = Int` | `Int` |
| 4 | `fun x { x + 1 }` | 外层 `Γ₀` | 无 | `α -> Int` |
| 5 | `f` | `Γ₂` | 无 | `α -> Int` |
| 6 | 实参 `1` | `Γ₂` | 无 | `Int` |
| 7 | `f(1)` | `Γ₂` | `α -> Int = Int -> β` | fresh `β` |
| 8 | 整个 `let` | 外层 `Γ₀` | 无 | `β` |

遍历结束：

$$
C=\{\alpha=\mathrm{Int},\quad
      (\alpha\to\mathrm{Int})=(\mathrm{Int}\to\beta)\}
$$

整个程序的候选类型是 `β`。虽然函数体已要求 `α = Int`，这里还没有把替换应用到 `Γ₂`，所以环境暂时仍写作 `f : α -> Int`。

### 4.3 作用域结束不会撤销类型约束

离开函数体后，参数名字 `x` 不再可见，但它的类型变量 `α` 仍出现在函数类型中，`α = Int` 也仍然有效。

**名字的可见范围与类型等式的有效性需要分别维护。** 不能因为退出参数作用域，就丢弃函数体对参数类型提出的约束。

## 5. 合一：求出满足所有等式的替换（p.35–42）

### 5.1 合一的状态与目标

```text
E = 待解类型等式
S = 已经得到的替换

初始：E = C，S = {}
成功：E = {}，S 同时满足所有原始等式
```

对于原始约束中的每个 `T = U`，成功结果必须满足：

$$
S(T)=S(U)
$$

这里求解的是**类型相等约束**。隐式转换、子类型或重载选择需要各自的规则，不能因为某个值允许转换，就把两个不同类型直接合一。

### 5.2 四种基本操作

| 操作 | 适用等式 | 动作 |
| --- | --- | --- |
| Delete | `T = T` | 删除恒等式 |
| Orient | `T = α`，T 不是变量 | 改写为 `α = T` |
| Decompose | `F(T1,…,Tn) = F(U1,…,Un)` | 拆成各参数对应相等 |
| Eliminate | `α = T`，且 `α ∉ FV(T)` | 记录 `α ↦ T`，向其余等式和已有替换传播 |

箭头也是类型构造器，具有两个参数：

$$
(A_1\to A_2)=(B_1\to B_2)
\quad\Longrightarrow\quad
A_1=B_1,\ A_2=B_2
$$

`List(α)=List(Int)` 也可以分解为 `α=Int`。`List` 在这里是说明合一可扩展性的例子，尚未加入前面的 SimpleType 核心语法。

### 5.3 对上一节约束执行合一

| 步骤 | 操作 | 剩余 E | 已知 S |
| --- | --- | --- | --- |
| 初始 | — | `{α=Int, α→Int=Int→β}` | `{}` |
| 1 | Eliminate α | `{Int→Int=Int→β}` | `{α↦Int}` |
| 2 | Decompose | `{Int=Int, Int=β}` | `{α↦Int}` |
| 3 | Delete | `{Int=β}` | `{α↦Int}` |
| 4 | Orient | `{β=Int}` | `{α↦Int}` |
| 5 | Eliminate β | `{}` | `{α↦Int, β↦Int}` |

应用替换后：

```text
x                     : Int
fun x { x + 1 }       : Int → Int
f                     : Int → Int
f(1)                  : Int
整个 let              : Int
```

### 5.4 替换复合不能简化成字典合并（补充实现）

假设先解出 `α = β`，后来又解出 `β = Int`：

```text
S₁ = { α ↦ β }
S₂ = { β ↦ Int }

S₂ ∘ S₁ = { α ↦ Int, β ↦ Int }
```

本文约定：

$$
(S_2\circ S_1)(T)=S_2(S_1(T))
$$

新替换要更新旧替换的右侧。例如 `α ↦ Int -> β` 遇到 `β ↦ Int` 后，应得到 `α ↦ Int -> Int`。

实现也可以保留指向其他变量的链接，并在查询时追踪、压缩路径；但语义必须等价于完整复合。下面的伪代码采用显式传播。

### 5.5 合一器骨架（补充实现）

```text
unify(E):
    S = identity

    while E is not empty:
        (A, B) = E.pop()
        A = apply(S, A)
        B = apply(S, B)

        if A == B:
            continue                       // Delete

        if B is TypeVar and A is not TypeVar:
            swap(A, B)                     // Orient

        if A is TypeVar:
            if A in FV(B):
                fail("occurs check")
            Q = { A ↦ B }
            E = apply(Q, E)
            S = compose(Q, S)              // Q ∘ S
            continue

        if sameConstructorAndArity(A, B):
            E.addAll(zip(A.arguments, B.arguments))
            continue                       // Decompose

        fail("type constructor mismatch")

    return S
```

这里 `==` 比较类型结构；类型变量按唯一身份比较。处理 `α = α` 时应先 Delete，不能直接因 `α ∈ FV(α)` 就报告 occurs check 失败。

## 6. 合一失败的两类原因（p.43–44）

### 6.1 Occurs check：不能把变量替换为包含自己的有限类型

```text
fun x { x(x) }
```

推导过程：

```text
x : α
callee x   : α
argument x : α
结果类型 β = fresh()

[APP] 生成：α = α → β
```

若尝试代回：

```text
α = α → β
  = (α → β) → β
  = ((α → β) → β) → β
  = ...
```

不存在满足该等式的有限类型树。因此 Eliminate 必须检查：

$$
\alpha\notin FV(T)
$$

**补充理解：** 这里的拒绝基于本讲的有限简单类型模型。它不表示所有语言都必须禁止自应用，也不否定上一讲的递归数据类型。显式递归类型有自己的形成、等价与使用规则，不能通过直接删除 occurs check 来代替。

### 6.2 构造器冲突：固定结构无法靠替换改变

| 待解等式 | 失败原因 |
| --- | --- |
| `Int = Bool` | 基本类型不同 |
| `Int = α -> β` | 整数类型与函数构造器不同 |
| `List(α) = Tree(α)` | 顶层构造器不同 |
| `Int -> Int = Bool -> Int` | 分解后出现 `Int = Bool` |

变量可以被替换，但 `Int`、`Bool`、箭头等固定构造器不能被替换成彼此。

## 7. 课堂练习：高阶函数的完整推导（p.45–46）

```text
fun f -> Int {
    f(1) + f(2)
}
```

参数 `f` 没有标注，返回类型显式写为 `Int`。

### 7.1 创建变量并生成约束

```text
f      : α
f(1)   : β
f(2)   : γ
```

| 来源 | 约束 |
| --- | --- |
| 第一次调用 | `α = Int -> β` |
| 第二次调用 | `α = Int -> γ` |
| 加法左操作数 | `β = Int` |
| 加法右操作数 | `γ = Int` |
| 显式返回标注 | 主体 Int 与标注 Int 相等，可省略恒等式 |

候选函数类型为 `α -> Int`。

### 7.2 合一并回填

```text
E₀ = { α=Int→β, α=Int→γ, β=Int, γ=Int }

消去 α：
    S = { α↦Int→β }
    E = { Int→β=Int→γ, β=Int, γ=Int }

分解、删除恒等式：
    E = { β=γ, β=Int, γ=Int }

选择 β=Int 消去并传播：
    S = { α↦Int→Int, β↦Int }
    E = { Int=γ, γ=Int }

消去 γ，删除剩余恒等式：
    S = { α↦Int→Int, β↦Int, γ↦Int }
    E = {}
```

最终：

$$
\boxed{(\mathrm{Int}\to\mathrm{Int})\to\mathrm{Int}}
$$

函数接收一个 `Int -> Int` 的函数作为参数，返回 `Int`。外层参数类型的括号不能省略成 `Int -> Int -> Int`，两者含义不同。

## 8. 单态环境为什么不够（p.47–49、53–54）

```text
let id = fun x { x } in
    (id(1), id(true))
```

`id` 的函数体直接返回参数，候选类型为 `α -> α`，没有约束要求 α 必须是某个基本类型。

但如果环境只记录一个单态类型：

```text
Γ(id) = α → α
```

两次使用便共享同一个 α：

| 使用点 | 调用约束 | 分解后的要求 |
| --- | --- | --- |
| `id(1)` | `α -> α = Int -> β₁` | `α=Int`，`β₁=Int` |
| `id(true)` | `α -> α = Bool -> β₂` | `α=Bool`，`β₂=Bool` |

合在一起得到 `Int = Bool`，因而失败。调用规则本身正确；要允许通用的 `id` 分别作用于不同类型，就要改变环境中的绑定形式和查询规则。

**补充理解：** 课件在此引入二元组记法。本文把它视为扩展：若两项分别为 `T1`、`T2`，则 `(e1,e2) : T1 × T2`，不要求两项类型相同。它不属于 p.13 列出的最初核心文法。

## 9. Generalize：把独立的未知数变成类型参数（p.50、52、55）

### 9.1 Type 与 TypeScheme

```text
单态类型 T：
    Int
    α → α
    Int → β

类型方案 σ（TypeScheme）：
    ∀α. α → α
    ∀α β. α → β → α
```

本文用“单态类型”表示**不含全称量化符的类型表达式**，其中仍可包含待求解的类型变量。类型方案则显式记录哪些变量允许在使用点重新选择。

| 形式 | 含义 |
| --- | --- |
| `α -> α` | α 是一个共享的未知数；后续约束会影响所有相关位置 |
| `∀α. α -> α` | α 是类型参数；每次使用这个方案可独立实例化 |
| `∀∅. Int` | 没有量化变量，相当于普通的 Int 类型 |

环境由此扩展为：

```text
Γ : Name → TypeScheme

id ↦ ∀α. α → α
n  ↦ Int
```

**补充实现：** 若 Resolver 已建立 Symbol，仍然可以用 `Symbol → TypeScheme`。多态改变类型信息的表示，无需放弃上一讲的名字绑定结果。

### 9.2 为什么要先求解再泛化

两个定义看起来都含 α，但意义不同：

| 定义 | 候选类型 | 已有约束 | 求解后 |
| --- | --- | --- | --- |
| `fun x { x }` | `α -> α` | 无 | `α -> α` |
| `fun x { x + 1 }` | `α -> Int` | `α = Int` | `Int -> Int` |

第二个函数已经要求参数为 `Int`，不能在忽略约束的情况下把它泛化为 `∀α. α -> Int`。

对于纯的、非递归 `let x=e1 in e2`，基本顺序是：

```text
推导 e1 → 求解当前相关约束 → 应用替换
        → 判断哪些变量可泛化 → 绑定 x → 推导 e2
```

### 9.3 完整泛化条件（补充推导）

课件 p.55 说明还必须排除来自外部环境的变量。将这个条件写全：

$$
\operatorname{generalize}(\Gamma,T)
=\forall\bigl(FV(T)\setminus FV(\Gamma)\bigr).\,T
$$

若刚刚获得替换 S，则用更新后的类型和环境计算：

$$
\sigma=
\operatorname{generalize}(S(\Gamma),S(T))
$$

可泛化的变量必须同时满足：尚未被求解固定，并且不与外部环境共享。

自由类型变量按结构计算：

```text
FV(Int) = FV(Bool) = {}
FV(α) = {α}
FV(T1 → T2) = FV(T1) ∪ FV(T2)
FV(∀α1…αn. T) = FV(T) − {α1,…,αn}
FV(Γ) = 环境中所有类型方案的自由变量的并集
```

例如：

```text
Γ = { y : β }
T = α → β

FV(T) − FV(Γ) = {α, β} − {β} = {α}
generalize(Γ, T) = ∀α. α → β
```

α 可以由每个使用点选择；β 仍表示环境中 `y` 的那个类型，必须继续共享。

### 9.4 忽略环境会错误接受程序（补充推导）

设外部环境有 `x : α`：

```text
let y = x in
    (y + 1, if y then 1 else 0)
```

`y` 只是外部 `x` 的别名，因此 `FV(α) ⊆ FV(Γ)`，不能将 y 泛化成 `∀α. α`。

正确推导中，所有 y 共享 α：

```text
y + 1       要求 α = Int
if y ...    要求 α = Bool
合一失败
```

如果错误地泛化 y，两次使用就能分别实例化为 `Int` 和 `Bool`，使同一个外部值被当成两个不兼容类型。`FV(Γ)` 的排除条件正是为了保留这种依赖。

## 10. Instantiate：每次使用创建独立实例（p.51、54–55）

### 10.1 实例化只替换量化变量

```text
instantiate(∀α1…αn. T):
    为每个 αi 创建 fresh βi
    返回 T[α1↦β1, …, αn↦βn]
```

同一次实例化中，同一个量化变量的所有出现必须映射到同一个新变量：

```text
∀α. α → α   ⇒   δ → δ       正确
∀α. α → α   ⇒   δ → ε       错误：丢掉输入输出同型关系
```

不同次实例化则使用不同变量：

```text
第一次查询 id：α₁ → α₁
第二次查询 id：α₂ → α₂
```

对于 `∀α. α -> β`，只能 freshen α；自由变量 β 继续与外部环境共享。

### 10.2 `id` 的两次调用现在可以共存

```text
let id = fun x { x } in
    (id(1), id(true))
```

| 阶段 | 类型处理 |
| --- | --- |
| 推导初始化式 | 得到 `α -> α`，没有类型等式限制 α |
| let 定义点 | 外部环境为空，泛化为 `∀α. α -> α` |
| 第一次查询 id | 实例化为 `α₁ -> α₁` |
| `id(1)` | `α₁ -> α₁ = Int -> β₁`，得到 `α₁=β₁=Int` |
| 第二次查询 id | 实例化为 `α₂ -> α₂` |
| `id(true)` | `α₂ -> α₂ = Bool -> β₂`，得到 `α₂=β₂=Bool` |
| 整体结果 | `Int × Bool` |

两个使用点没有共享 α₁、α₂，所以不会产生 `Int = Bool`。

### 10.3 Generalize 与 Instantiate 对照

| 操作 | 典型发生点 | 输入 | 输出 |
| --- | --- | --- | --- |
| Generalize | let 定义处 | 已求解的类型与环境 | 类型方案 |
| Instantiate | 变量使用处 | 类型方案 | 含 fresh 变量的单态类型 |
| Unify | 求解约束时 | 类型等式 | 替换，或失败 |

**补充理解：** 类型方案的实例化描述的是静态类型处理。它本身不规定运行时是否复制函数，也不规定编译器必须为每种类型生成一份机器码；那些属于具体语言的实现策略。

## 11. Hindley–Milner 与 Algorithm W（p.56–57）

### 11.1 HM 的核心组成

课件将以下机制联系为 Hindley–Milner（HM）类型推导的核心：

```text
类型变量 + 类型规则产生约束 + 合一
            + let 定义点泛化 + 使用点实例化
```

前半讲可以先遍历整棵 AST 收集单态等式，最后统一求解。**加入 let 多态后，必须在泛化前完成相关求解，不能照搬“全部生成完才处理”的单态流程。** Algorithm W 将递归推导、合一和替换传播交织起来。

### 11.2 W 的关键分支（补充实现）

下面只展示纯函数、调用、变量与非递归 let。约定 `W(Γ,e)` 返回 `(S,T)`，其中 T 已反映本次推导得到的替换。整数、布尔值和运算符可按前文规则补充。

```text
W(Γ, x):
    return (identity, instantiate(Γ(x)))

W(Γ, fun x { body }):
    α = fresh()
    (S, Tbody) = W(Γ[x ↦ α], body)       // 参数保持单态
    return (S, S(α) → Tbody)

W(Γ, f(a)):
    (S1, Tf) = W(Γ, f)
    (S2, Ta) = W(S1(Γ), a)
    β = fresh()
    S3 = unify({ S2(Tf) = Ta → β })
    return (S3 ∘ S2 ∘ S1, S3(β))

W(Γ, let x = e1 in e2):
    (S1, T1) = W(Γ, e1)
    Γ1 = S1(Γ)
    σ = generalize(Γ1, T1)
    (S2, T2) = W(Γ1[x ↦ σ], e2)
    return (S2 ∘ S1, T2)
```

理解时重点看三个位置：

- 推导后面的子表达式前，用此前替换更新环境。
- 推导 `let` 主体前，使用求解后的类型和环境泛化。
- 查询方案时实例化；普通函数参数作为零量化方案，仍共享原来的类型变量。

**补充实现：** 对类型方案应用替换时，只替换自由变量；需要时重命名量化变量以避免捕获。不能把 `∀α. α -> α` 中受绑定的 α 当作环境中的待解 α 随意改写。

### 11.3 let 多态不等于任意位置都能多态（补充理解）

比较：

```text
let id = fun x { x } in (id(1), id(true))    // 允许

fun id { (id(1), id(true)) }                // 经典 HM 中拒绝
```

第二段的 `id` 是函数参数，只有一个单态类型。它必须同时满足 `Int -> β` 和 `Bool -> γ`，合一失败。

若希望函数参数本身具有 `∀α. α -> α` 这样的类型，就需要超出这里的普通 HM 参数规则，研究高阶多态及相应标注机制。

### 11.4 Principal type：保留最一般的合法类型

恒等函数的最一般类型方案是：

$$
\forall\alpha.\ \alpha\to\alpha
$$

`Int -> Int`、`Bool -> Bool`，乃至 `(Int -> Bool) -> (Int -> Bool)` 都是它的实例。推导器不应因为缺少约束就任意挑选 `Int`，否则会损失通用性。

经典 HM 核心系统对可类型化程序提供最一般类型方案，类型推导可判定。Damas 与 Milner 的论文证明了相应算法的完备性；这些结论有其语言模型前提，不能直接推广到任意重载、子类型或高阶多态扩展。见 [Principal Type-Schemes for Functional Programs](https://opencourse.inf.ed.ac.uk/sites/default/files/https/opencourse.inf.ed.ac.uk/itcs/2024/damas-milner.pdf)。

课件给出的历史脉络：1969 年 Hindley 研究组合逻辑中的最一般类型；1978 年 Milner 在 ML 背景下提出类型推导算法 W；1982 年 Damas 与 Milner 系统化相关证明。

## 12. 推导范围：局部声明何时确定类型（p.58–60）

类型规则能够利用哪些上下文、何时停止收集信息，都属于语言设计。

### 12.1 Java 的 `var`

```java
var x = null;    // 编译错误
```

Java 局部变量的 `var` 从声明处的初始化式推导类型；后续赋值不会回头为这个声明选择类型。`null` 字面量具有特殊的 null type，规范禁止将它作为这里推导出的局部变量类型。见 [JLS §14.4.1](https://docs.oracle.com/javase/specs/jls/se25/html/jls-14.html#jls-14.4.1)。

**补充理解：** 这不表示所有“运行时值可能为 null”的初始化式都不能使用 var。例如 `var x = (String) null;` 的初始化式具有 `String` 类型，能提供类型信息。

### 12.2 C++ 局部变量的 `auto`

```cpp
#include <initializer_list>

auto xs = {};       // 无法推导元素类型
auto ys = {1, 2};   // std::initializer_list<int>
```

这种花括号初始化按照相应模板推导规则确定元素类型；空列表没有元素可提供证据。后续语句不会补救已经失败的声明。见 [C++ 工作草案：Placeholder type deduction](https://eel.is/c++draft/dcl.spec.auto#dcl.type.auto.deduct) 与 [Deducing template arguments from a function call](https://eel.is/c++draft/temp.deduct.call)。

课件的另一个例子是：

```cpp
auto xs = new X;    // 假设 X 已定义且可构造，xs 的类型为 X*
```

初始化式虽然创建对象，但表达式本身的类型是指针，因此推导结果也是指针类型。

**补充理解：** 本节只讨论普通局部变量声明，不能概括 C++、Java 所有推导机制。泛型调用、C++ 函数返回类型等有自己的规则。课件强调的是：局部推导可以让类型更容易在附近读懂，错误也更接近信息来源。

## 13. 多态与可变引用：为什么需要 value restriction（p.61–62）

### 13.1 两种灵活性会在同一个格子上冲突

用课件的 ML 风格伪代码：

```text
let r = ref(fun x { x })
```

其中 `ref(e)` 创建可变存储格，`!r` 读取格子，`r := e` 写入格子。

我们可能希望同时支持：

```text
(!r)(42)
(!r)(true)

r := fun (x : Int) { x + 1 }
```

但运行时只有一个格子。写入 `Int -> Int` 函数后，再把读出的函数用于 `Bool`，就会发生类型不一致。

### 13.2 错误泛化会产生什么问题（补充推导）

假设错误地赋予共享格子：

```text
r : ∀α. Ref(α → α)
```

则可以出现：

```text
r := fun (x : Int) { x + 1 }    // 将 r 实例化为 Ref(Int → Int)
(!r)(true)                     // 又实例化为 Ref(Bool → Bool)
```

两次静态实例化指向同一个运行时格子。第二行读到的实际值是刚写入的整数函数，并没有一个新的布尔函数。

这说明前面针对纯表达式使用的自动泛化规则，不能不加限制地用于分配可变状态的表达式。

### 13.3 量词位置不同，承诺也不同

| 类型形式 | 承诺 | 对写入整数专用函数的处理 |
| --- | --- | --- |
| `∀α. Ref(α -> α)` | 同一个引用可在使用时被视为不同元素类型 | 对此共享可变格子进行这种泛化会导致不安全 |
| `Ref(∀α. α -> α)` | 格子内始终保存一个通用函数 | 拒绝只支持 Int 的函数 |
| `Ref(α -> α)`，α 不泛化 | 格子具有一个共享、待确定的单态函数类型 | 可以将 α 约束为 Int，此后所有使用都遵守它 |

课件给出的两种安全方向是：

1. **限制写入**：使用 `Ref(∀α. α -> α)`，要求每次写入的函数本身都支持所有实例。它需要扩展类型系统，超出前面的普通 HM 类型方案位置。
2. **限制读取的多态性**：引用保持单态，允许写入与格子类型相符的函数。ML 的 value restriction 采用这一方向。

### 13.4 Value restriction 与弱类型变量

value restriction 限制 let 泛化：基本做法允许对函数值等非扩张表达式泛化，对 `ref(...)` 这样的分配表达式保留单态未知数。OCaml 将后一类未知数显示为弱类型变量，例如：

```ocaml
let r = ref (fun x -> x);;
(* r : ('_weak1 -> '_weak1) ref *)

r := (fun x -> x + 1);;
(* 此后 r : (int -> int) ref *)

(!r) true;;
(* 类型错误：需要 int *)
```

弱变量表示一个待确定的类型，后续约束一旦将其确定，就对所有相关使用生效。OCaml 还采用 relaxed value restriction，允许一些仅出现在协变位置的变量安全泛化。见 [OCaml Manual：Polymorphism and its limitations](https://ocaml.org/manual/5.5/polymorphism.html)。

**补充理解：** “此后固定”描述静态推导或交互式顶层中信息逐渐确定的过程，不能理解为程序运行时动态改变类型。限制也不是只靠搜索源码中是否出现 `ref`；函数调用可能隐藏持久的可变状态。

## 14. 公共接口为什么仍值得显式标注（p.63–64）

课件的 Scala 例子：

```scala
// 局部或 private 实现可以省略返回类型
private def double(x: Int) = x * 2

// 公共接口明确写出返回契约
def double(x: Int): Int = x * 2
```

Scala Style Guide 建议所有公共成员标注返回类型，把它作为由编译器验证的文档，也帮助避免实现变化无意改变接口类型。见 [Scala Style Guide：Declarations](https://docs.scala-lang.org/style/declarations.html#methods)。

显式标注的工程作用包括：读者无需进入函数体即可理解调用契约；实现变化必须继续满足声明；接口和二进制兼容性更容易维护。它并不自动保证所有兼容性问题都消失。

**这是接口设计建议，不意味着示例中未标注返回类型的 public 方法一定无法编译。** 编译器能否推导，与团队是否要求契约可见，是不同层面的决定。

## 15. 推导器还需要处理歧义与诊断（p.65–66）

### 15.1 五项设计决定

| 设计问题 | 本讲的选择或例子 |
| --- | --- |
| AST 节点产生什么约束 | `x + 1` 要求 `type(x)=Int` |
| 哪些结构可以合一 | 同构造器逐项分解，检查构造器冲突和 occurs check |
| 哪里允许泛化 | 纯 HM 的 let；加入可变状态后还要限制 |
| 重载、默认类型如何参与 | 需要候选匹配、上下文、转换规则和优先级 |
| 如何解释冲突 | 保存约束的源码来源与推导过程 |

这些选择共同决定语言接受哪些程序，不能完全归为求解器内部细节。

### 15.2 重载需要比等式合一更多的信息

```text
候选：print(x : Int)
      print(x : Float)

调用：print(1)
```

在本讲 SimpleType 中，整数常量直接是 `Int`。在更丰富的语言中，候选可能为实参提供期望类型，还要考虑字面量规则、隐式转换和候选优先级。

**补充理解：** 这两个候选通常是备选方案，不能无条件把它们的要求同时加入同一个合取约束集合。求解器还需要表达选择，或由重载解析过程逐个筛选。具体选择哪个候选，由语言规定。

### 15.3 类型错误应指出冲突的两处来源

```text
let f = fun x { x + 1 } in
    f(true)
```

```text
函数体 x + 1：要求 x 为 Int
调用 f(true)：提供 Bool

冲突：Int = Bool
```

只报告“合一失败”不利于定位问题。更有用的诊断是：

```text
f 的参数需要 Int，因为其函数体将参数用于整数加法；
这里传入的实参 true 是 Bool。
```

**补充实现：** 约束可记录为：

```text
Constraint {
    leftType,
    rightType,
    sourceSpan,
    reason,
    parentConstraints
}
```

分解等式或传播替换时保留原因链，最终错误才能回溯到最初要求发生的位置。引入多态后，即使初始化式的约束已经求解，也应保留类型来源，供使用处的错误诊断引用。

## 17. 易错点与复习速查

| 常见误解 | 应当记住的条件 |
| --- | --- |
| 每遇到一次变量名就 fresh | 单态绑定复用类型；多态使用仅 freshen 量化变量 |
| `α -> α` 已经天然允许多种独立类型 | 需要类型方案以及使用点实例化 |
| 函数调用前必须已知 callee 是箭头类型 | 可先生成 `Tf = Ta -> β` |
| 加法返回 Int，所以无需保存约束 | 还必须保存两个操作数为 Int 的要求 |
| 求解只修改最终返回类型 | 环境、AST 中相关类型和旧替换也要一致更新 |
| 新替换直接并入字典就够了 | 要按顺序复合，并传播到旧映射的右侧 |
| occurs check 会拒绝 `α = α` | 恒等式先 Delete；拒绝的是产生无限展开的绑定 |
| 所有未解变量都可以泛化 | 排除环境自由变量，并遵守语言的泛化限制 |
| let 多态就是函数参数多态 | 经典 HM 的普通函数参数保持单态 |
| 加入多态后仍可把所有普通等式留到最后 | let 泛化前必须求解相关约束，或使用显式表达这种依赖的更丰富机制 |
| 合一能自动处理所有隐式转换 | 类型相等、可转换和重载选择是不同关系 |
| weak type variable 可以每次选择新类型 | 它是一个共享的单态未知数 |
| 公共接口的显式类型只会增加冗余 | 它也是编译器检查的文档与演化边界 |

手工推导时，可以按以下顺序完成：

1. 写出当前环境，给缺失的参数类型创建 fresh 变量。
2. 按 AST 处理顺序，分别记录候选类型和新增约束。
3. 遇到调用，明确写出“被调用类型 = 实参类型 → fresh 结果类型”。
4. 合一时跟踪 E 与 S，处理分解、传播和失败条件。
5. 遇到可泛化的 let，先求解，再计算 `FV(T) − FV(Γ)`。
6. 在多态变量使用点实例化，最后把替换应用到整体类型。

## 18. 自测题与参考答案（补充练习）

### 18.1 推导函数应用器

```text
fun f { fun x { f(x) } }
```

设 `f : α`、`x : β`，调用结果为 fresh γ，约束为：

```text
α = β → γ
```

候选类型是 `α -> β -> γ`，替换后得到：

$$
(\beta\to\gamma)\to\beta\to\gamma
$$

在空环境的 let 定义处，可以泛化为 `∀β γ. (β -> γ) -> β -> γ`。

### 18.2 判断条件分支是否同型

```text
fun x { if x then 1 else false }
```

条件要求 `type(x)=Bool`；两个分支又要求 `Int=Bool`，因此失败。未知参数可求解，不代表不同的固定类型可以被合并。

### 18.3 判断哪些变量可以泛化

```text
Γ = { y : β }
T = α → β → α
```

因为 `FV(T)={α,β}`、`FV(Γ)={β}`，泛化结果是：

```text
∀α. α → β → α
```

实例化后例如得到 `δ -> β -> δ`，β 不变。

### 18.4 区分多态使用与单态自应用

```text
A: fun x { x(x) }

B: let id = fun x { x } in id(id)
```

A 中两次 x 共享 α，得到 `α=α->β`，occurs check 失败。

B 中两个 id 分别实例化：

```text
callee id   : α₁ → α₁
argument id : α₂ → α₂
result      : β

α₁ → α₁ = (α₂ → α₂) → β
⇒ α₁ = α₂ → α₂
⇒ β = α₂ → α₂
```

没有变量被迫等于包含自己的类型，因而推导成功，结果为 `α₂ -> α₂`。这也说明“语法上把一个名字传给同名函数”不足以判断是否触发 occurs check，关键在于两处类型变量是否共享。

### 18.5 对比两种函数定义

```text
let id = fun x { x } in (id(1), id(true))
let inc = fun x { x + 1 } in (inc(1), inc(true))
```

第一段中 α 可泛化，结果为 `Int × Bool`。第二段的参数早已受加法约束固定为 Int，`inc(true)` 失败；泛化不会把函数已经具有的要求抹去。
