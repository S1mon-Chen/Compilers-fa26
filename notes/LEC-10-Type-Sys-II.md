# LEC 10 · 类型推导、合一与 let 多态

SE3355 编译原理 · 2026 秋　[本讲课件（68 页）](../lectures/LEC-10-Type-System-II.pptx)

`fun x { x + 1 }` 没写参数类型，但整数加法已经要求 `x:Int`，所以函数类型是 `Int → Int`。类型推导把这些要求写成等式，再求一组能让等式同时成立的替换。省去标注的程序仍可以在运行前完成类型检查。页码从封面计数，课件后半部分有几处页脚编号重复。

## 从 AST 生成约束（p.2–34）

用新变量 `α` 代表一个未知类型。同一个参数的各次使用共享这个变量，独立的未知类型分别取新名。若 `S = {α ↦ Int}`，把 S 应用于 `α → α` 得到 `Int → Int`。函数类型里的每个出现位置都要替换。

下表先讨论**单态**推导。每个节点收集子表达式产生的等式，再加入自己的等式。`fresh` 表示生成尚未用过的类型变量。

| 表达式 | 子节点或环境提供的类型 | 本节点新增约束 | 返回的候选类型 |
| --- | --- | --- | --- |
| 整数 `n` | 无 | 无 | `Int` |
| `true` / `false` | 无 | 无 | `Bool` |
| 变量 `x` | `Γ(x)=T` | 无 | `T` |
| `e1 + e2` | `T1`、`T2` | `T1=Int`，`T2=Int` | `Int` |
| `e1 < e2` | `T1`、`T2` | `T1=Int`，`T2=Int` | `Bool` |
| `if c then a else b` | `Tc`、`Ta`、`Tb` | `Tc=Bool`，`Ta=Tb` | `Ta` |
| `fun x { e }` | 在 `Γ[x↦α]` 中推导主体得到 `Tb` | 无额外等式，α 为 fresh | `α -> Tb` |
| `f(a)` | `Tf`、`Ta` | `Tf = Ta -> β`，β 为 fresh | `β` |
| `let x=e1 in e2` | 先得 `T1`，再在 `Γ[x↦T1]` 中得到 `T2` | 单态版本无额外等式 | `T2` |

课件的完整例子是 `let f = fun x { x + 1 } in f(1)`。令 `Γ₀ = ∅`，进入函数体用 `Γ₁ = {x:α}`，进入 let 主体时暂用 `Γ₂ = {f:α→Int}`。名字 `x` 离开了作用域，关于 α 的约束却继续有效，因为 f 的类型仍引用它。

| 顺序 | 节点 | 环境 | 新增约束 | 返回类型 |
| --- | --- | --- | --- | --- |
| 1 | `x` | `Γ₁` | 无 | `α` |
| 2 | 函数体中的 `1` | `Γ₁` | 无 | `Int` |
| 3 | `x + 1` | `Γ₁` | `α = Int` | `Int` |
| 4 | `fun x { x + 1 }` | 外层 `Γ₀` | 无 | `α -> Int` |
| 5 | `f` | `Γ₂` | 无 | `α -> Int` |
| 6 | 实参 `1` | `Γ₂` | 无 | `Int` |
| 7 | `f(1)` | `Γ₂` | `α -> Int = Int -> β` | fresh `β` |
| 8 | 整个 `let` | 外层 `Γ₀` | 无 | `β` |

## 合一怎样解这些等式（p.35–46）

求解器维护剩余等式 E 和已有替换 S。同一构造器两边对应的部分分别求解。例如，两个箭头相等要求参数类型和返回类型分别相等。不同的固定构造器（如 `Int` 和 `Bool`）无法靠替换变得一样。

| 操作 | 适用等式 | 动作 |
| --- | --- | --- |
| Delete | `T = T` | 删除恒等式 |
| Orient | `T = α`，T 不是变量 | 改写为 `α = T` |
| Decompose | `F(T1,…,Tn) = F(U1,…,Un)` | 拆成各参数对应相等 |
| Eliminate | `α = T`，且 `α ∉ FV(T)` | 记录 `α ↦ T`，向其余等式和已有替换传播 |

对前面的 `f(1)`，先用 `α = Int` 替换另一个等式里的 α，再拆开箭头。

| 步骤 | 操作 | 剩余 E | 已知 S |
| --- | --- | --- | --- |
| 初始 | — | `{α=Int, α→Int=Int→β}` | `{}` |
| 1 | Eliminate α | `{Int→Int=Int→β}` | `{α↦Int}` |
| 2 | Decompose | `{Int=Int, Int=β}` | `{α↦Int}` |
| 3 | Delete | `{Int=β}` | `{α↦Int}` |
| 4 | Orient | `{β=Int}` | `{α↦Int}` |
| 5 | Eliminate β | `{}` | `{α↦Int, β↦Int}` |

因此整个程序的类型是 `Int`。合一求的是**最一般合一子**（MGU），只固定约束所要求的部分。例如单独求解 `α = β`，得到 `{α ↦ β}` 就够了，β 仍可选作任何类型。若先有 `α ↦ β`、再解得 `β ↦ Int`，旧替换的右侧也要更新。复合替换 `S₂ ∘ S₁` 的意思是先应用 S₁、再应用 S₂，简单拼接两张映射表可能让 α 停在 β。

**合一失败有两种常见原因。** `if c then 1 else false` 要求 `Int = Bool`，是构造器冲突。`fun x { x(x) }` 中，设 `x:α`、调用结果为 β，则要满足 `α = α → β`。把右侧代回会无限展开。*Occurs check* 在绑定前检查 α 是否出现在右侧，拒绝这种有限类型无法满足的方程。`α = α` 本身已经成立，应先删除。

**课堂练习。** `fun f -> Int { f(1) + f(2) }` 中，给参数 f 类型 α，给两次调用的结果分别起名 β、γ。用两个实参和加法列出四个约束，就能推得 f 本身的函数类型。

```text
E₀ = { α=Int→β, α=Int→γ, β=Int, γ=Int }

消去 α：
    S = { α↦Int→β }
    E = { Int→β=Int→γ, β=Int, γ=Int }

分解、删除恒等式：
    E = { β=γ, β=Int, γ=Int }

选择 β=Int 消去并传播：
    S = { α↦Int→Int, β↦Int }
    E = { Int=γ, γ=Int }

消去 γ，删除剩余恒等式：
    S = { α↦Int→Int, β↦Int, γ↦Int }
    E = {}
```

所以整个函数类型为 `(Int → Int) → Int`。括号内是它接收的那个函数的类型。

## 同一个 id 为什么能接受两种类型（p.47–57）

若 `let id = fun x { x }` 只在环境里登记 `id : α → α`，随后的 `id(1)` 会令 α 等于 Int，`id(true)` 又要令同一个 α 等于 Bool。**let 多态**给绑定保存一个类型方案（type scheme），例如 `∀α. α → α`。每次使用可为 α 选择新实例，但同一次使用的参数和返回值必须同型。

| 时机 | 操作 | 例子 |
| --- | --- | --- |
| 绑定 `let x = e₁` | 先推导并求解 e₁，把替换 S 用到环境和类型上。只量化 `FV(S(T)) − FV(S(Γ))` 中的变量。 | 恒等函数可存为 `∀α. α → α`。`fun x { x + 1 }` 已解为 `Int → Int`，没有可量化的变量。 |
| 查找 `x` | 实例化方案，把每个**量化变量**一致地换成一个新变量，自由变量仍共享。 | 两次查询 id 分别得到 `α₁ → α₁`、`α₂ → α₂`。调用后可分别得到 Int、Bool。 |

`FV` 指自由类型变量。为什么要减去环境中的变量？若 Γ 已有 `x:α`，再写 `let y = x in (y + 1, if y then 1 else 0)`，两个 y 读的是同一个外部值。α 必须同时是 Int 和 Bool，所以应拒绝。如果把 y 随意泛化，就会错误地让两次使用分别选择类型。

Hindley–Milner（HM）的核心包括合一、let 定义处泛化和使用处实例化。在其纯核心语言中，可类型化的表达式具有最一般类型（principal type），其他合法类型可由它实例化得到。Algorithm W 边递归边传递替换。下面的 `W(Γ,e)` 返回替换和已应用该替换的结果类型。符号 `∘` 表示从右到左依次应用替换。

```text
W(Γ, x):
    return (identity, instantiate(Γ(x)))

W(Γ, fun x { body }):
    α = fresh()
    (S, Tbody) = W(Γ[x ↦ α], body)       // 参数保持单态
    return (S, S(α) → Tbody)

W(Γ, f(a)):
    (S1, Tf) = W(Γ, f)
    (S2, Ta) = W(S1(Γ), a)
    β = fresh()
    S3 = unify({ S2(Tf) = Ta → β })
    return (S3 ∘ S2 ∘ S1, S3(β))

W(Γ, let x = e1 in e2):
    (S1, T1) = W(Γ, e1)
    Γ1 = S1(Γ)
    σ = generalize(Γ1, T1)
    (S2, T2) = W(Γ1[x ↦ σ], e2)
    return (S2 ∘ S1, T2)
```

普通函数形参保持单态，因此 `fun id { (id(1), id(true)) }` 在经典 HM 中失败。若改成 let 定义的恒等函数，两次使用可以独立实例化。[Damas 与 Milner 的主类型方案论文](https://opencourse.inf.ed.ac.uk/sites/default/files/https/opencourse.inf.ed.ac.uk/itcs/2024/damas-milner.pdf)

## 一旦有可变存储，哪些东西还能泛化（p.61–62）

假设 `r = ref(fun x { x })` 创建了**一个**可读写的格子。若给 r 类型 `∀α. Ref(α → α)`，写入时就可以选 Int，读出时又选 Bool，于是类型系统会放行下面两行代码。

```text
r := fun (x:Int) { x + 1 }
(!r)(true)
```

两次使用访问同一个格子。第二行实际调用的是整数函数。要使读取和写入相容，可以固定格子的元素类型，也可以约束允许写入的函数。

- 固定格子的元素类型。`Ref(α → α)` 中的 α 不泛化，第一次写入把它固定为 Int 后，第二行就会报错。ML 的 *value restriction* 限制可泛化的绑定，分配可变引用的表达式会留下共享的单态未知数。[OCaml 的弱类型变量与值限制](https://ocaml.org/manual/5.5/polymorphism.html)
- 要求格子始终存放多态函数。`Ref(∀α. α → α)` 允许不同类型的读取，但第一行的整数专用函数不能写入。要在引用内部表示这种量词，需要比上述 HM 核心更丰富的类型系统。

## 语言设计决定推导看到多少上下文（p.58–60、63–68）

- **局部变量。** Java 的 `var x = null;` 和 C++ 的 `auto xs = {};` 都无法从初始化式确定所需类型。Java 的 `var x = (String)null;` 则给出了足够信息。后面的赋值不会回头补全这些声明。[Java 局部变量推导](https://docs.oracle.com/javase/specs/jls/se25/html/jls-14.html#jls-14.4.1) · [C++ 占位类型推导](https://eel.is/c++draft/dcl.spec.auto#dcl.type.auto.deduct)
- **公共接口。** 显式返回类型让调用方直接读到约定，也让实现改动引起的类型变化在函数本身被发现。课件以 Scala 的公共方法为例。[Scala 方法声明风格](https://docs.scala-lang.org/style/declarations.html#methods)
- **重载与诊断。** `print(Int)` 和 `print(Float)` 都可选时，还需判断允许的转换及候选优先级。对 `f(true)` 与函数体 `x + 1` 的冲突，保留两个约束各自的 span，就能同时指出“调用传入 Bool”和“函数体要求 Int”。
- **延伸方向。** System F 将类型抽象写入语言，双向类型检查区分“推导类型”和“按期望类型检查”。类型类与 trait 描述所需能力，效应类型追踪可能执行的操作，线性类型约束值的使用次数。

## 自测

1. `fun f { fun x { f(x) } }` 的最一般类型是什么？设 `x:β`，`f(x):γ`，唯一必要约束是 `f:β→γ`。结果为 `(β→γ) → β → γ`。
2. Γ 中已有 `y:β`，推得 `α → β → α`，能量化谁？只有 α。一次实例化可以得到 `δ → β → δ`，中间的 β 仍与 y 共享。
3. `let id = fun x { x } in id(id)` 也会卡在 occurs check 吗？两个 id 分别实例化为 `α₁→α₁` 和 `α₂→α₂`。调用令 `α₁ = α₂→α₂`，结果也为 `α₂→α₂`，没有循环方程。
