# LEC 2 · 词法分析与正则表达式

SE3355 编译原理 · 2026 秋　[本讲课件（40 页）](../lectures/LEC-2-Lexical-Analysis-I.pptx)

`print("a b");` 中，引号里的空格属于字符串，紧挨着的 `)` 和 `;` 却是两个词。词法分析器（Lexer）从当前位置尝试各条规则，挑出一个词素（lexeme），再按规则决定返回哪种 Token、跳过它，还是切换扫描模式。

## Parser 从 Lexer 拿到什么（p.2–16）

以 `int y = x + 1;` 为例，偏移从 0 开始。Lexer 也会读过空格，以便正确定位下一个词。

| Lexeme（匹配文本） | Token | 起始偏移（从 0 开始） |
| --- | --- | --- |
| `int` | `KW_INT` | 0 |
| `y` | `IDENT("y")` | 4 |
| `=` | `ASSIGN` | 6 |
| `x` | `IDENT("x")` | 8 |
| `+` | `PLUS` | 10 |
| `1` | `INT_LITERAL(1)` | 12 |
| `;` | `SEMICOLON` | 13 |

语法分析器根据当前状态和 Token 的 `kind` 选择动作。`lexeme` 是源码原文，`value` 是解码后的值。若语言允许十进制前导零，`0042` 和 `42` 可以有相同的整数值，却占用不同长度的源码。`span` 记录位置，例如 `int` 占字节区间 `[0,3)`。课件也用从 1 开始的行、列表示区间。含中文时需明确列按字节还是字符计算。

调用 `nextToken()` 可以依次得到这些记录。Parser 看到 `int y = x + ;` 时，能凭 `SEMICOLON` 判断加号后缺了操作数，再用它的 `span` 指向出错的位置。格式化器还可以把空格和注释保存为 *trivia*。

## 一条正则描述哪些词素（p.17–22）

给定字母表 Σ，Σ* 是所有有限字符串的集合。语言是它的一个子集。正则表达式描述一个**正则语言**。`ε` 是长度为零的字符串，`{ε}` 有一个元素，`∅` 没有元素。

| 构造 | 记号 | 含义 |
| --- | --- | --- |
| 单字符 | `'c'` | 只匹配字符 `c`，语言为 `{ "c" }` |
| 空串 | `ε` | 匹配长度为 0 的字符串，语言为 `{ "" }` |
| 连接 | `AB` | 先匹配 A，再匹配 B |
| 选择 | `A \| B` | 匹配 A 或 B，语言为 `L(A) ∪ L(B)` |
| Kleene 星号 | `A*` | 将 A 重复零次或多次 |

重复比连接结合得紧，连接又比选择结合得紧。例如 `ab*|c` 可以匹配 `a`、`abb` 或 `c`。`A+` 等于 `AA*`，`A?` 等于 `(A|ε)`。字符类 `[0-9]` 匹配一位数字。`[^"\n]` 匹配双引号和换行以外的一个字符。

| Token | 课堂模式 | 边界例子 |
| --- | --- | --- |
| 整数 | `[0-9]+` | 整段 `42` 合法。若语言把负号作为运算符，`-42` 分成两个 Token。 |
| 标识符 | `[A-Za-z_][A-Za-z0-9_]*` | `_x2` 合法。`2x` 不能整体充当标识符。 |
| 简化字符串 | `"[A-Za-z0-9 ]*"` | 两个双引号都是词素的一部分。`""` 和 `"a b"` 合法。 |

判断“整个字符串是否属于这个语言”和“当前位置能读出多长的词”是两种操作。用上述规则扫描 `2x` 会先得到整数 `2`，再得到名字 `x`。这个排列能否出现在程序中由语法规则决定。

## 多条规则同时匹配时怎样选（p.23–35）

一条词法规则包含模式和动作。空白匹配 `[ \t\r\n]+` 后可以执行 `skip`，整数匹配后可以转成数值并执行 `emit`。同一位置的选择顺序是**先比长度，再比规则顺序**。只有命中同一个最长前缀的规则才需要比优先级。

| 输入 | 从开头能匹配什么 | 本轮的结果 |
| --- | --- | --- |
| `if` | 关键字和标识符都匹配 2 个字符 | 关键字规则在前，返回 `KW_IF`。 |
| `ifx` | 关键字匹配 2 个，标识符匹配 3 个 | 返回 `IDENT("ifx")`。 |
| `foo+3` | `f`、`fo`、`foo` 都是标识符 | 返回 `IDENT("foo")`，下一轮从 `+` 开始。 |
| `<<=1` | 若有 `<`、`<<`、`<<=` 三条规则，三者都能成功 | 返回 `SHIFT_LEFT_ASSIGN`，下一轮从整数 `1` 开始。 |

直接实现时，让每条有效规则尝试匹配当前位置的**非空前缀**，取它能接受的最长长度，再从所有候选中做上述选择。下面把同一段源码和第二行的扫描结果放在一起。该行的 `int` 从第 5 列开始，`;` 占第 18 列。

```c
int adjust(int x) {
    int y = x + 1;
    return y;
}
```

```text
KW_INT       [2:5,  2:8)
IDENT(y)     [2:9,  2:10)
ASSIGN       [2:11, 2:12)
IDENT(x)     [2:13, 2:14)
PLUS         [2:15, 2:16)
INT(1)       [2:17, 2:18)
SEMICOLON    [2:18, 2:19)
```

普通 Token 规则若能匹配空串，`nextToken()` 可能在同一位置反复成功。文件末尾可单独返回 `EOF`。

## 错误与词法模式（p.36–38）

若当前位置没有任何规则可以接受，例如 `int y = x @ 1;` 中的 `@`，记录这个字符的位置，并按规约跳过它或返回错误 Token。恢复后必须有进展。若扫描器只是为了寻找更长的词而多读了字符，则应退到最近一次接受的位置。第 3 讲给出实现。[从自动机生成 Lexer](LEC-3-Lexical-Analysis-Impl-of-RE.md)

模式（mode）记录当前启用哪组规则。在普通代码中，开引号让 Lexer 记下起点并进入字符串模式。在字符串模式中，空格追加到内容，闭引号才结束字符串并返回普通模式。在此之前遇到 EOF，可以把“字符串未闭合”的诊断指回开引号。

**复习题里的例子。** 在消息体中读到保留字段名 `ws`，扫描器进入等待冒号的模式，读到 `:` 后才进入 `WS_VALUE`。所有模式都允许的换行只会被跳过，因此 `ws`、冒号和值可以分三行写。把字段名换成 `wsx`，整段会走普通字段规则。前一个例子检验换行后能否留在原模式，后一个检验是否读完了最长字段名。[期中复习课件，第 39、53–56、62 页](../lectures/LEC-17-Midterm-Review.pptx)

## 把一段规格拆成正则（期中复习题）

题目要求双引号内是一个 `ws://` 地址。域名首段至少含一个字母，后面至少再跟一个非空的点分段。最后的十六进制串可以全用大写字母和数字，也可以全用小写字母和数字。把域名首段、其余域名和路径分别写出来，就能逐段核对。

```regex
"ws://[0-9]*[A-Za-z][A-Za-z0-9]*(\.[A-Za-z0-9]+)+/([0-9A-F]+|[0-9a-f]+)"
```

首段的 `[A-Za-z]` 保证至少有一个字母，其前的数字可以为零个。末尾两支是对**整段**二选一。若写成 `[0-9A-Fa-f]+`，便会错误接受 `"ws://api.com/A1b2"`。`"ws://127.0.0.1/ABC"` 错在首段全是数字，`"ws://api.com/123"` 则合法。

同一题要求正则本身排除字段名 `ws`。单靠“关键字规则排在前面”只会改变扫描动作，不会让 `[A-Za-z]+` 描述的集合少掉这个串。可把合法名字拆成四类，分别是单个 `w`、首字符不是 `w`、以 `w` 开头但第二个字母不是 `s`、以 `ws` 开头且还有后缀。[期中复习课件，第 29–35 页](../lectures/LEC-17-Midterm-Review.pptx)

```regex
w|[A-Za-vx-z][A-Za-z]*|w[A-Za-rt-z][A-Za-z]*|ws[A-Za-z]+
```

## 自测

1. 若题目只允许 `0` 或无前导零的有符号十进制整数，且排除 `-0`，怎样描述整段词素？用 `0|-?[1-9][0-9]*`。`012` 和 `-0` 都不属于该语言。扫描整份输入时还要结合规则与上下文判断是否报错。
2. `"a b"` 的 kind、lexeme、value 分别是什么？在上面的简化规约里，kind 为 `STRING`，lexeme 含两个引号，value 是三个字符 `a`、空格、`b`。
3. 规则只有 `a` 和 `abc`，面对 `abx` 能否在 `b` 处立刻报错？扫描器读到 `ab` 时仍可能等来 `c`。读到 `x` 后，它先交付早先接受的 `a`，下一轮回到 `b`。
