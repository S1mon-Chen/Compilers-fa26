# LEC 1 · 编译器怎样翻译程序

SE3355 编译原理 · 2026 秋　[本讲课件（30 页）](../lectures/LEC-1-Introduction.pptx)

编译器读入源程序，检查它是否符合语言规则，再生成行为符合源语言规定的目标程序。源语言规定的返回值、输出及副作用的先后次序，都是翻译时要保留的行为。

## 从一行 C 到机器指令（p.15–21）

`int add1(int x) { return x + 1; }` 在课件采用的 x86-64 调用约定下可以译成下面三条指令。

```asm
add1:
    mov  eax, edi    ; 取整数参数 x
    add  eax, 1
    ret              ; 整数结果放在 eax
```

输入 `41`，调用者拿到 `42`。同一行源码在编译器内会经历几种表示，每种表示都回答一个具体问题。

| 阶段 | 在 `return x + 1;` 上做什么 |
| --- | --- |
| 词法分析 | 从字符中认出 `RETURN IDENT("x") PLUS INT(1) SEMI`，记下各自的位置。 |
| 语法分析 | 生成 `Return(Add(Name("x"), Int(1)))`。加法属于返回语句。 |
| 名字解析、类型检查 | 把这里的 `x` 连到形参声明，检查加法和返回值的类型。 |
| 中间表示（IR） | 写出“取 `x`、加一、返回结果”的执行步骤。优化器可以查询谁定义了一个值、谁在用它。 |
| 后端 | 选择目标指令，把参数、临时值和结果安排到寄存器或内存。 |

把 `x` 改成一个未声明的 `y`，语法分析仍能建出同样形状的树，名字解析会在 `y` 处报错。把 `+ 1` 改成 `+ 2` 则可能顺利编译。算法是否符合作者的意图，还要用规格和测试来判断。

## 为什么要换表示（p.16–21）

- **AST**（抽象语法树）保留程序的嵌套关系。从 `Return` 的子节点就能找到要返回的表达式。语法分析树还记录文法展开的步骤和标点。
- **CFG**（控制流图）用边连接基本块。遇到 `if`，沿两条出边可以找到各自执行的代码。
- **SSA**（静态单赋值形式）给每次定义单独取名。沿加法的操作数可以直接找到产生该值的指令。一份 IR 可以同时具有 CFG 和 SSA 这两种结构。
- **Machine IR**（机器级中间表示）写出目标机支持的指令和操作数。多个临时值同时活跃、寄存器又不够时，后端可将部分值暂存到内存，需要时再读回，这叫 *spill*。

前端负责识别结构、绑定名字和检查类型。中端利用 IR 分析、改写程序。例如 `a = 2; b = a + 3; return b` 中，先把 `a` 替换成 `2`，再算出 `2 + 3 = 5`，最后只需 `return 5`。能删去前两步，是因为这两次局部计算没有别的可观察效果。

后端把 IR 译成机器指令。运行时则在程序执行期间提供服务。例如，编译器确定对象布局并生成分配调用，分配器在运行时提供空间，垃圾收集器根据当时还可达的对象决定哪些空间可以回收。

## 语言规则怎样帮助系统设计（p.23）

| 系统问题 | 语言能提供什么信息 |
| --- | --- |
| Shell 怎样筛选 CPU 占用较高的进程？ | 给输出定义列名和类型，就可以按数值比较 `CPU > 20`。 |
| 分布式共享内存怎样协调读写？ | 所有权规则可以约束同一对象的写者与读者，系统据此安排访问。 |
| 协程暂停后怎样继续？ | 先明确要保存的执行位置、寄存器和栈等状态，恢复时才能从暂停处接着运行。 |

**自测。** 对 `return 7;` 和 `print(7); return 7;`，只比较函数返回值，能证明两者等价吗？第二段还会输出一个 7。如果优化器因为返回值相同就删掉打印，调用者仍能从输出观察到差异。

## 课程与 Lab（p.2–13、22、24–30）

旧版 Lab 逐步实现 Tiger 编译器，最终生成 LLVM IR。新版允许学生在给定风格内设计语法，并用测试说明语言规则。比如，若规定内层变量能遮蔽外层变量，就写一个程序分别在块内、块外读同名变量，看能否得到两个预期值。拿到模型写的名字解析器时，也可以反过来用这段程序检验它，再解释结果为什么符合自己的作用域规则。课件把这两种能力称为“建构”和“解构”。
